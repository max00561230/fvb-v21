## Immediate Cause: page-090 Before 87/88/89

`page-090` was displayed after display page 89 but before the intended late sequence because `scripts/page-metadata.mjs` hard-coded `ACTIVE_PAGE_IDS` as:

```js
[
  "page-001",
  "page-003",
  "page-004",
  "page-005",
  "page-006",
  ...Array.from({ length: 81 }, (_, index) => `page-${String(index + 8).padStart(3, "0")}`),
  "page-091",
  "page-089",
  "page-002",
  "page-090",
]
```

That expansion keeps `page-087` at active position 85 and `page-088` at active position 86, then appends `page-091`, `page-089`, `page-002`, and `page-090` as active positions 87 through 90. `scripts/build-page-assets.mjs` then turns that array into `pageNumber` values through `pageNumberForPageId()` and sorts generated pages with `pages.sort((a, b) => a.pageNumber - b.pageNumber)`. Therefore the exact ordering cause is the hard-coded `ACTIVE_PAGE_IDS` array in `scripts/page-metadata.mjs`, consumed by `pageNumberForPageId()`, and materialized by the `pages.sort(...)` calls in `scripts/build-page-assets.mjs`.

## Required Correction Direction

Create one authoritative reading-order manifest with rows:

```json
{
  "pageId": "page-001",
  "readingPosition": 1,
  "displayNumber": 1,
  "originalPrintedPageNumber": null,
  "sourceFile": "page-001.png"
}
```

Every generated runtime manifest, OCR/search output, reader lookup, thumbnail order, navigation, and validation report must derive from that manifest. `pageId`, OCR filename, source filename, original printed page number, and directory order must not independently control active visible sorting.
